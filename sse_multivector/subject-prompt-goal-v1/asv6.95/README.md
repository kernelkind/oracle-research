## Hypothesis and contract

ASv6.94 instructs the model to complete each source subject across all compatible
headings, but its worked outputs traverse one numbered branch at a time. The
candidate demonstrates the existing collection instruction by emitting the
copies together. This is a new example-order comparison, not a new semantic
rule or a claim that the model's hidden procedure follows its output order.
Neither exact-string copying nor grouped output is made mandatory for answers.
Equivalent subjects, all complete source qualifications, scope, partial/shared
actions and every compatible numbered occurrence retain the same criteria.

The numbered graph is identical to ASv6.94. Production subjects validation
requires each parent to precede its children, not numeric preorder or contiguous
subtrees. Read-only consumer inspection finds the same preceding-parent
requirement in subject parsing and hierarchy refresh; subject-order probing
explicitly sorts numeric labels. Fresh answers must retain their own array
index/mask bindings. This candidate does not reorder any saved processed output.
All 34 primary instruction clauses and five tracked implications retain the
same example assignments and demonstrations.

The already-bound ASv6.94 N096 trial 1 is a production copy failure before this
revision: it forms the complete recipe-qualified saute but leaves compatible
ingredient-list copies empty. That behavior is the target; the offline test is
only an authored-example check. Before revision, the production-validated ASv6.94
example fails that check because C1 separates copies of the complete shared cut.
After revision all 129 relevant checks pass, including every original C1 scope
and copy obligation, tuple preservation and finite ancestry.
