# ASv6.13 versus ASv6.17

**Evidence:** Unlinked data file references below identify local originals outside this checkout. See [publication availability](../../../docs/experiments/README.md#reading-the-research-records).

Neither prompt passes. ASv6.17 improves some context-dependent subjects but also introduces errors that ASv6.13 avoids.

Both unchanged prompts received the same 28 development notes, once each, through fresh isolated Sol-low calls. The prompt order alternated between notes; calls ran sequentially. The final-validation notes were not used.

| Prompt | Notes with no error or unresolved judgment | Accepted subjects |
| --- | ---: | ---: |
| ASv6.13 | 21/28 | 254/271 (93.7%) |
| ASv6.17 | 19/28 | 147/172 (85.5%) |

Broad, nested, overlapping and duplicate subjects remain allowed. Fewer subjects are not inherently better, and one valid list need not match another exactly. These counts describe this run under the recorded assistant review, not population accuracy.

## What changed in the outputs

| Notes | ASv6.13 | ASv6.17 |
| --- | --- | --- |
| D07 — Musical Chairs | Adds a social-media setting not named in the note. | Omits that addition. |
| D10 — Riley Walz | Several items say only “the hiring”; one analyst item lacks its topic. | Preserves the hiring/assessment context in those items. |
| D13 — sports supplements | Omits the UK context supplied by the hashtags. | Preserves that context. |
| D25 — CEO question | Describes the unfinished “hi” and leaves later event references unresolved. | Extracts the recoverable question and supplies CEO context. |
| D14 — mirrored link | Returns no subjects, appropriately. | Turns the mirroring credit into a subject. |
| D19 — dashboard | Uses the dashboard description outside the URL. | Copies the URL-only name into every subject. The assessments themselves remain supported. |
| D21 — meditation quotation | Represents the quotation's meaning. | Adds a bibliographic-credit subject referring to “this view.” |
| D22 — hacking advertisement | Uses the unnamed provider and its stated services. | Derives “Cloud Force Solutions” from the URL and uses it in every subject. |
| D24 — insurance report | Omits presentation metadata. | Extracts the confidence label; “The Council” also leaves the source ambiguous, not proven misattributed. |
| D26 — spaceflight crew | Represents the mission announcement. | Adds an image-position subject from the caption's C/R markers. |

The other 15 notes have no identified error or unresolved judgment under either prompt.

Three notes remain unclean under both prompts:

- D08: the literal-flight reading of “Snow was still fly” remains unresolved to the reviewer. ASv6.13 also preserves the supported stylish/impressive reading; ASv6.17 omits it. No image was inspected.
- D12: the reviewer has not established the meaning of “HosKasi Laguma Karo.” This is not evidence of a known extraction omission. ASv6.17's proposed translation remains unresolved too.
- D23: ASv6.13 invents counts of entries. ASv6.17 preserves number–label pairings and the block number, but individual entries still omit their Bitcoin-fee/mempool meaning. This is a partial improvement, not a passing result.

## What this establishes

The latest prompt's gains on the earlier CEO diagnostic do not establish that it is a better prompt overall. In this fresh comparison, four notes improve and six regress by the fixed review standard. ASv6.13 also varies across repeated full runs: its earlier audited result was 24/28, compared with 21/28 here.

This does not isolate which instruction caused a change, prove that every observed difference is repeatable, or establish a best overall prompt. It does identify a broader tradeoff to investigate instead of automatically extending the newest version.

The next controlled test restores only ASv6.13's sentence about content versus presentation in ASv6.17. Repeated metadata and URL-identifier cases will test the suspected effect; event-reference and numeric cases will check what is lost. No other prompt wording, model setting or acceptance criterion should change in that comparison.
