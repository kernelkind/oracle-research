# Bootstrap-v103 current-AS qualification

Bootstrap establishes a standalone information-topic meaning for one original
local entry. It does not compare canonical nodes or construct a hierarchy.
The user approved [Bootstrap-v103](Hierarchy-bootstrap-v103.md) and qualification
on the current 344-case collection. Full-collection qualification is pending;
approval does not activate a production prompt.

## Input and review contract

All current subject inputs must originate from the approved ASv6.100 template,
SHA-256 `0e3fdfb713128233ba65070c0092914a38b0059a2eb5e873c0d828add1c5d52f`.
Verify native producer receipts, not merely a version label. Earlier AS data and
downstream results remain historical evidence. Historical user decisions guide
review but do not predetermine the meanings of changed ASv6.100 entries.

Input schema 4 supplies the full original post, the complete original tree under
the selected entry's root, and its selected number. There are no generated
parent meanings, expected labels or preferred outputs in the model input.
The post supplies factual evidence; the selected subject, contexts and original
tree guide category interpretation. Output schema 79 supplies ambiguities,
resolutions, a nullable final meaning and exact contiguous evidence quotes.

Review final meanings for supported identity, abstraction and explicit material
boundaries. General categories are broader than their illustrated instances.
Preserve required roles, purposes, states and defining actions without inventing
facts about a particular occurrence. Diagnostic wording alone does not fail a
clear final meaning. Assess independently generated children against the exact
independently generated ancestors from their own draw; do not broaden a parent
during review or splice preferred endpoints across draws. Joint descriptions
and independently admitted alternatives require different inclusion checks.
Nulls remain unresolved producer coverage, not negative comparison labels.

## Native execution and integration

Use the shared stable runner from an isolated task worktree. New dispatch uses
the shared automatic queue, at most 30 requests host-wide; historical concurrency
32 is frozen metadata, not a current setting. Reuse requires identical native
request identity. `--repeat` deliberately requests an independent draw.
Do not change a checkout bound to an active experiment.

Full-v103 preparation inherits exact cases and settings from the completed
`bootstrap-v98-full-v1` experiment through native `prepare --from`, replacing
only the prompt with v103 and deriving its new cache prefix/key. It uses the
existing shared 20,000-attempt counter; fresh attempts, warmups, retries and
failures count. Exact reuses are separately attributed and are not new samples.

Bootstrap support is integrated without legacy hierarchy/experiment-runtime
changes: source-bound schema-4 collection reconstruction, optional controlled
post/context diagnostics, and a receipt-bound meaning-diagnostic adapter.
Controlled evidence cannot be substituted as original local evidence for
canonical comparison. The regression test for diagnostic preparation failed
before this support was added because the adapter was unknown. No Compare
prompt activation, hierarchy generation, UI refresh or external agent message
is part of this qualification.

The isolated integration passes 92 production-path checks: 66 node-pair and
Bootstrap adapter tests, nine fixed-meaning adapter tests, eleven consistency
tests and six native hierarchy-shaping tests. An initial command named two
nonexistent modules; the actual consistency and shaping modules were then run.
An additional shaping-selection suite is unavailable in plain Python without
